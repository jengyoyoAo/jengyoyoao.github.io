Project Euler · Problem 3

Largest Prime Factor

Find the largest prime factor of 600,851,475,143.

Project Euler 3Posted October 25, 2026View original problem ↗

Key idea

I used trial division: when a factor divides the number, divide it out and check the smaller result again. After checking 2, test odd factors. If no factor up to the square root divides the remaining number, that remainder is the largest prime factor.

Implementation

Solution

n = 600851475143
ans = -1

def factorization(n):
    global ans
    if n % 2 == 0: return factorization(n//2)
    for i in range(3, int(n**0.5)+1, 2):
        if n % i == 0:
            ans = max(ans, i)
            return factorization(n//i)
    ans = max(ans, n)

factorization(n)
print(ans)
#include <stdio.h>
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main(void){
    long long n = 600851475143LL;
    long long ans = -1;

    while (n % 2 == 0) {
        ans = MAX(ans, 2);
        n /= 2;
    }

    for (long long i = 3; i * i <= n; i += 2) {
        while (n % i == 0) {
            ans = MAX(ans, i);
            n /= i;
        }
    }

    ans = MAX(ans, n);

    printf("%lld\n", ans);
    return 0;
}

Both versions output 6857 for this input. The Python code stays close to my original recursive version. I adjusted the C entry point to int main(void) and added parentheses to the MAX macro. The Python even-number branch does not update ans, but that does not affect this odd input.

Why it works

The code tries factors in increasing order. When a factor divides the number, it divides it out and continues with the smaller quotient. The last remaining value greater than 1 has no smaller factor left to check, so it is prime. For the given input, both programs print 6857.

Complexity

Let n be the original input value.

  • Time: O(√n) trial divisions in the worst case.
  • Extra space: O(log n) recursion depth in the Python version; O(1) in the C version.

Takeaway

Removing a factor makes the next search smaller. This is the straightforward trial-division approach I used; the C version uses a standard int main(void) entry point, while the Python even-number case could be handled more completely by updating ans before recursing.
