Project Euler · Problem 4

Largest Palindrome Product

Find the largest palindrome made from the product of two three-digit numbers.

Project Euler 4Posted October 25, 2026View original problem ↗

Key idea

Check products of two three-digit numbers and reverse the digits to test whether each product is a palindrome. Keep the largest palindrome found instead of returning at the first match.

The two implementations use the same arithmetic palindrome check: repeatedly take the last digit with modulo 10, append it to the reversed number, and remove it from the original number using integer division. Starting the inner loop at j = i avoids checking both i × j and j × i.

For each fixed i, the product decreases as j decreases. If num <= ans, break only the inner loop: smaller values of j cannot improve the maximum. The next outer-loop iteration must still be checked because its inner loop restarts at a larger j.

Solution

def is_palindrome(num):
    n, m = num, 0
    while num != 0:
        m = m * 10 + num % 10
        num //= 10
    return m == n


ans = -1
for i in range(999, 99, -1):
    for j in range(i, 99, -1):
        num = i * j
        if num <= ans:
            break
        if is_palindrome(num):
            ans = num
print(ans)
#include <stdio.h>
#define MAX(a, b) (a > b ? a : b)

int is_palindrome(long long num){
    int n = num, m = 0;
    while (num != 0){
        m = m * 10 + num % 10;;
        num /= 10;
    }
    return m == n;
}

int main(void) {
    long long num;
    long long ans = -1;
    for (int i = 999; i >= 100; i--){
        for (int j = i; j >= 100; j--){
            num = i * j;
            if (num <= ans) {
                break;
            }
            if (is_palindrome(num)) {
                ans = num;
            }
        }
    }
    printf("%lld\n", ans);
    return 0;
}

Both the Python and C versions print 906609 = 993 × 913. The C solution is my revised version. Its palindrome helper uses int for the original and reversed values; both fit the products in this problem on a 32-bit-or-larger int implementation.

Why it works

Every unordered pair of three-digit factors appears with 100 ≤ j ≤ i ≤ 999. Reversing the decimal digits identifies palindromes, and ans stores the largest one seen. For a fixed i, products decrease as j decreases, so once a product is no larger than ans, the remaining products in that inner loop cannot improve it. The final result is therefore the largest palindrome product.

Complexity

  • Time: O(N² log n), where n is the upper factor bound; each digit reversal takes O(log n) time.
  • Extra space: O(1).

A faster approach: mirror a prefix

Generate six-digit palindromes in descending order by mirroring a three-digit prefix. For example, prefix 906 becomes 906609. Instead of testing whether every product is a palindrome, test whether each palindrome has two three-digit factors.

Every six-digit palindrome is divisible by 11 because its alternating digit sum is zero. Since 11 is prime, at least one factor must be divisible by 11. The inner loop therefore checks three-digit multiples of 11 and verifies that the quotient is also a three-digit integer. Palindromes are generated from largest to smallest, so the first valid factorization gives the maximum.

ans = -1

for prefix in range(999, 99, -1):
    num = prefix
    n = prefix

    while n != 0:
        num = num * 10 + n % 10
        n //= 10

    for i in range(110, 1000, 11):
        if num % i == 0:
            j = num // i
            if 100 <= j <= 999:
                ans = num
                break

    if ans != -1:
        break

print(ans)

This implementation searches only six-digit palindromes. It finds 906609 = 993 × 913, so shorter palindromes cannot improve the result for this problem. A general solver must also search shorter palindromes if no six-digit candidate has a valid factorization.

Complexity

Let n be the upper factor bound for a generalized search over d-digit factors. There are O(n) mirrored candidates, each requiring O(log n) digit operations to construct and at most O(n) trial divisions. The total is O(n log n + N²) = O(N²) time and O(1) extra integer variables under the same unit-cost arithmetic model used above. The factor-of-11 shortcut reduces constant work, not the Big O.

A small improvement to the pair search

The main solutions can also stop the outer loop when i * i <= ans. Because j ≤ i, no product in the current or later rows can improve the maximum. This pruning does not change the stated O(N² log n) upper bound.

Takeaway

Descending loop variables do not guarantee that all products are visited in descending order. Keep a running maximum, and only stop a search when the remaining candidates cannot improve it.
